### Blocker resolved

`ChangePasswordUseCase` injected `AUTH_PASSWORD_PORT` with nothing providing it, so Nest's
eager singleton instantiation threw during bootstrap. The port was also unimplementable:
`IAuthPasswordPort.changePassword` had no counterpart in the Auth BC.

`AuthService.changePassword()` now verifies the current password with bcrypt `compare`,
rejects inactive accounts, hashes the new password and persists via the repository port.
`AuthPasswordAdapter` in the User BC's outbound adapters satisfies the port by delegating
to `AUTH_SERVICE`, keeping the User BC free of Auth domain types. `UserModule` binds the
token and imports `AuthModule`; no cycle, since `AuthModule` does not import `UserModule`.

The endpoint also took untyped `@Body('oldPassword')` / `@Body('newPassword')` strings and
accepted any value as a new password. It now uses `ChangePasswordDto` with the same
strength rules `RegisterDto` already enforced.

### Wrong HTTP statuses

`GlobalExceptionFilter` dispatches on `DomainError` subclass names, so every bare
`throw new Error(...)` reached clients as a 500. Missing catalog, product and profile
returned 500 instead of 404; absent identity 500 instead of 401; invalid email, password
and user id 500 instead of 400. All eight now use the matching subclass. Nine use cases
also moved from NestJS `NotFoundException` to `NotFoundError`, satisfying CLAUDE.md's rule
that the application layer depends on the `Injectable` decorator only — both map to 404,
so behaviour is unchanged.

## Newly found — not fixed

1. **`CatalogDeleted` flow is dead at both ends.** `CatalogDeletedEvent` exists but nothing
   constructs it: `ArchiveCatalogUseCase` saves without emitting, and `Catalog.archive()`
   collects no event. On the consumer side `CatalogDeletedHandler` is declared
   `@EventsHandler()` with no event class, so `@nestjs/cqrs` subscribes it to nothing.
   `checkpoint-2026-07-10-01` listed the handler as a delivered component.
   Fixing it needs a decision on how a BC subscribes to another BC's event without
   importing its domain type.
2. **`Password.isStrongPassword` is unreachable.** Both `register` and `changePassword`
   construct `new Password(hash, true)`, and the `hashed` branch skips validation.
   Strength is enforced by the DTOs instead, so behaviour is correct, but the VO rule is
   dead code.
