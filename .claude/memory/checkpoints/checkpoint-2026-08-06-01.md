## Blocker — the application cannot start

`ChangePasswordUseCase` injects `AUTH_PASSWORD_PORT`. No provider anywhere in `src/` binds
that token, and `UserModule` imports no module exporting it. Nest instantiates singletons
eagerly, so `NestFactory.create(AppModule)` throws:

```
Nest can't resolve dependencies of the ChangePasswordUseCase (?).
Please make sure that the argument "AUTH_PASSWORD_PORT" at index [0] is available.
```

Reproduced against compiled `dist/`. The port is also unimplementable as designed:
`IAuthPasswordPort.changePassword()` has no counterpart in the Auth BC. `AuthService`
exposes `register`, `login`, `validateUser`, `getProfile` and a private `generateTokens` —
no password-change operation exists. `POST /auth/change-password` was never implemented
end to end, though `gate-001` for user-profile listed it as a completed use case.

This is feature work, not a wiring fix. It needs a scope decision: implement password
change in Auth and adapt it into User, or withdraw the endpoint and port until scheduled.
