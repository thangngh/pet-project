### The contract

A context may not import another context's domain types, so publisher and
subscriber had no class to share and each declared its own copy. That does not
work: `@nestjs/cqrs` stamps identifying metadata onto the exact class passed to
`@EventsHandler` and binds on it, so a copy with a matching name is a different
event.

Cross-context events now live in
`backend/src/shared/adapters/event-bus/integration-events/` and carry
primitives only, which is what keeps the subscriber free of the publisher's
domain. Both sides import the one class. The rules sit in a README beside them.

`EventBusService` moved from the Auth context to the shared event-bus module —
Catalog publishes now and cannot depend on Auth to do it.

### Why unit tests did not catch any of this

A handler bound to the wrong class, or to no class, still passes a test that
calls `handle()` directly. The new `integration-events.spec.ts` publishes
through the real bus instead. Reverting the decorator to `@EventsHandler()`
fails it.

Likewise TypeScript does not check dependency injection and unit tests do not
build a container, so an unbound token was invisible to both.
`app.bootstrap.spec.ts` resolves the whole graph with the database stubbed.
